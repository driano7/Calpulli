1. CONEXIÓN DEL JOURNEY DE LUCHAS A EVENTOS REALES (PUNTO 1)
--------------------------------------------------------------------------------

Objetivo: mostrar debajo de cada variante de arena (Arena México y Arena Coliseo)
los días y horarios de las próximas 7 funciones, alimentados por el scraper de
lucha que ya corre cada 3 días (vercel.json cron: "0 6 */3 * *").

Archivos CREADOS:
- components/journeys/LuchaArenaSchedule.tsx
  * Componente cliente ('use client').
  * Llama a GET /api/lucha/events?arena=<mexico|coliseo>&from=<hoy>&to=<hoy+7dias>.
  * La API lee de la tabla lucha_events en Turso (poblada por el scraper).
  * Si la API devuelve 0 eventos o falla, usa un fallback estático con los
    horarios recurrentes conocidos del scraper:
      Arena México: martes 19:30, viernes 20:30, domingo 17:00
      Arena Coliseo: jueves 19:00, sábado 19:30
  * Cada evento muestra: fecha, hora y enlace "Ver boletos" a cmll.com/tickets.
  * El panel se envuelve en GlassDark (variant="subtle") para estilo consistente.

Archivos MODIFICADOS:
- components/journeys/LuchasJourney.tsx
  * Importa LuchaArenaSchedule.
  * Debajo de cada tarjeta de variante (arena-mexico y arena-coliseo), dentro
    del <Reveal> pero fuera del <button> selector, renderiza
    <LuchaArenaSchedule arena={...} arenaName={...} isEs={...} />.
  * Así cada visitante ve, bajo la opción que elija, los próximos 7 días y
    horarios de esa arena específica, con enlace a boletos oficiales.

APIs involucradas:
- /api/lucha/events  (pages/api/lucha/events.ts)
  Parámetros: arena (mexico|coliseo), from (YYYY-MM-DD), to (YYYY-MM-DD).
  Devuelve { events: LuchaEvent[] }.
  También existe ?byWeek=true para agrupar por semana y arena.
- /api/cron/lucha-scraper  (pages/api/cron/lucha-scraper.ts)
  Endpoint protegido por CRON_SECRET que ejecuta el scraper cada 3 días.

¿La API funciona?
- Técnicamente SÍ: el endpoint existe, lee de Turso y el scraper escribe en
  lucha_events (initLuchaEventsTable + upsertLuchaEvent).
- El scraping LIVE de cmll.com no está inicializado (Playwright queda en null),
  por lo que el scraper usa el fallback estático getStaticEvents(). Eso es
  suficiente para mostrar horarios recurrentes reales de CMLL.
- Si el scraper nunca se ha ejecutado en producción, la tabla estará vacía y
  el componente mostrará el fallback estático (los mismos horarios conocidos).
- No es necesario buscar otras APIs: la fuente es CMLL (cmll.com) y los datos
  se guardan en Turso. Si se quiere scraping live real, habría que inicializar
  Playwright en scripts/scrapers/lucha-scraper.ts (línea 8: let browser = null).

CRON_SECRET en Vercel:
- Ir al dashboard de Vercel -> Proyecto Amaxing -> Settings -> Environment
  Variables.
- Agregar variable: CRON_SECRET = <mismo valor que usaban en GitHub Actions>.
- Esta variable protege el endpoint /api/cron/lucha-scraper (requiere header
  Authorization: Bearer <CRON_SECRET>).
- En Vercel, los Cron Jobs se configuran en vercel.json (ya listo) y se
  disparan automáticamente según el schedule.

Pasos para desplegar:
1. git add . && git commit -m "feat: conectar horarios de luchas al journey + glass dark UI + fix build"
2. git push origin master
3. Vercel detecta el push, ejecuta next build y despliega automáticamente.
4. Verificar en Vercel Dashboard > Cron Jobs que el scraper esté activo.
